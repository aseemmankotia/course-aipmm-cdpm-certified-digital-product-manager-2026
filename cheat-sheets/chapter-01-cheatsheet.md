## Chapter 1: Digital Product Management Foundations (~14% weight)

### Outcome vs Output
| | Definition | Example Metric |
|---|---|---|
| Output | What was built/shipped | Story points, releases, features shipped |
| Outcome | Resulting change in behavior/value | Conversion rate, retention, revenue per user |
**Exam rule:** Any answer citing only delivery activity (velocity, on-time shipping, Definition of Done) as 'success' is an output trap — pick the option measuring behavioral/business change.

### Project Team vs Persistent Product Team
| | Project Team | Persistent Product Team |
|---|---|---|
| Duration | Fixed scope/timeline | Ongoing, tied to product life cycle |
| Team fate | Disbands at launch | Stays intact, cross-functional |
| Accountability | Delivery of defined scope | Outcomes across discovery → delivery → growth |
| Fits | One-time launches, fixed migrations | Products needing continuous iteration |

### Continuous Delivery vs One-Time Launch
| | Continuous Delivery | One-Time Launch |
|---|---|---|
| Launch = | Start of iteration loop | End of initiative |
| Life cycle view | Ongoing product life cycle | Linear project completion |
| Team model fit | Persistent product team | Project team |

### Digital Product Life Cycle Stages
Discovery → Delivery/Build → Launch/Growth → Maturity → Decline/Sunset
- **Discovery:** validate problem/solution with users before building.
- **Delivery:** build and ship the validated solution.
- **Growth:** scale adoption, optimize via experimentation.
- **Maturity/Decline:** flat/falling usage, rising maintenance cost → shift to minimal-maintenance stance, plan retirement/migration.

### Vision-to-Strategy Cascade
Vision → Strategy → Roadmap → Backlog (abstract → concrete). Exam frequently scrambles this order — memorize exact sequence.

### Platform Product vs Data Product
| | Platform Product | Data Product |
|---|---|---|
| Core value | Shared capability enabling other products/teams | The dataset itself (quality, trust, accessibility) |
| Consumers | Internal/external teams building on top | Any team/system consuming curated data |
| Delivery mechanism | APIs, SDKs, shared services | APIs, feeds, dashboards — mechanism ≠ defining trait |

### Digital PM Role by Phase
| Phase | Primary PM Activity |
|---|---|
| Discovery | Interviews, prototypes, problem/solution validation |
| Delivery | Backlog prioritization, scope/quality tradeoffs, coordination |
| Growth | Experimentation, optimization, retention/expansion metrics |

### Choosing Operating Stance — Quick Rule
- Fixed scope + fixed deadline + disband after → **Project team**
- Ongoing iteration + unclear end state + evolving value → **Persistent product team**
- Flat usage + no roadmap + rising cost → **Sunset/minimal maintenance stance**

### Common Exam Traps
1. Confusing on-time/on-budget delivery with success (output vs outcome).
2. Assuming any API-exposed capability is automatically a 'platform product' (data products often use APIs too).
3. Choosing to 'extend the project' instead of transitioning to a persistent product team when ownership gaps appear post-launch.
