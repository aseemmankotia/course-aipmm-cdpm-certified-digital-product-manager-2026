## Chapter 4 Cheat Sheet — Lean Startup & Riskiest Assumption Testing

### Build-Measure-Learn Loop
| Step | Question it Answers | Exam Note |
|---|---|---|
| Learn (start here) | What do we need to know? | Work BACKWARDS from Learn to decide what to build |
| Measure | What metric proves/disproves the hypothesis? | Metric must be actionable, accessible, auditable |
| Build | What's the MINIMUM to run that measurement? | Not 'highest quality' — minimum viable test |
| Goal | — | **Minimize total loop time**, not build polish |

### Hypothesis Template (exact order — memorize)
```
We believe [doing X for persona Y] will result in [outcome].
We will know this is true when we see [measurable signal + threshold/timeframe].
Because [underlying evidence/reasoning].
```
Exam trap: any reordering, missing threshold, or missing 'because' clause = not well-formed.

### Riskiest Assumption
- **Riskiest ≠ first-listed ≠ easiest to test.**
- Formula: **Impact × Uncertainty** — highest combined score = test first (leap-of-faith assumption).
- If the business fails when this assumption is false → it's riskiest.

### Three Risk Categories
| Category | Question | Example Test |
|---|---|---|
| Desirability | Do users want it? | Concierge MVP, smoke test |
| Viability | Will it make money? | Landing page w/ real payment |
| Feasibility | Can we build/deliver it? | Wizard of Oz, technical spike |

### Cheapest Valid Test Selection
| Assumption Type | Cheapest Valid Test |
|---|---|
| Will they pay? | Landing page + real pre-order button |
| Do they want it? | Concierge MVP (manual delivery to real users) |
| Can we build it? | Wizard of Oz / prototype spike |
| Will they use it repeatedly? | Fake-door + usage tracking over time |

### Validated Learning vs Anecdotal Feedback
- **Validated learning:** tied to a measurable metric + real behavioral commitment (money, time, sign-up).
- **Anecdotal feedback:** verbal opinions/interview quotes, no commitment, no baseline.
- Exam trap: '3 users loved it' ≠ validated learning.

### Pivot vs Persevere
| Signal | Decision |
|---|---|
| Metric trending toward threshold | Persevere |
| Metric flat/missed + clear root cause identified | Pivot (change core hypothesis element) |
| One bad day/small sample | Neither — keep testing, don't overreact |

### Quick Memory Trick
**D-V-F** = **D**esirability, **V**iability, **F**easibility → "**D**o they want it, can we **V** make money, can we **F**inish building it."
