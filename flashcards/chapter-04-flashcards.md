## Chapter 4: Lean Startup and Riskiest Assumption Testing — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Build-Measure-Learn loop — correct working order and goal? | Work backwards: decide what you need to LEARN → design what to MEASURE → BUILD only the minimum to test it. Goal: minimize total cycle time through the loop, not build quality. |
| 2 | Well-formed hypothesis template — exact structure order? | We believe [action] will result in [outcome]. We will know this is true when [measurable signal, with threshold/timeframe]. Because [underlying reasoning/evidence]. |
| 3 | Riskiest assumption vs 'any' assumption — exam trap? | Riskiest = highest Impact × Uncertainty (leap-of-faith assumption, business-model-breaking if false). Exam trap: picking the easiest-to-test or first-listed assumption instead. |
| 4 | Three risk categories in MVP/Lean testing? | Desirability (do users want it), Viability (does the business model make money), Feasibility (can we technically build/deliver it). |
| 5 | Validated learning vs anecdotal feedback? | Validated learning = data from a rigorous test tied to a measurable hypothesis (ideally with a real behavioral commitment). Anecdotal feedback = unstructured opinions/quotes with no baseline or commitment. Exam trap: interview enthusiasm ≠ validated learning. |
| 6 | Pivot vs Persevere — decision criteria? | Persevere if metrics trend toward the hypothesis threshold over a valid test period. Pivot if metrics plateau/fall short with a clear root cause requiring a change to a core strategy element (value prop, segment, channel). |
| 7 | Cheapest valid test for a VIABILITY (willingness-to-pay) assumption? | Landing page with a real pre-order/payment button ('fake door' + payment intent) — measures real commitment cheaply before building the product. |
| 8 | Cheapest valid test for a FEASIBILITY (can-we-build-it) assumption? | Wizard of Oz test / technical spike — manually fake the backend behind a real front-end to confirm technical delivery is possible before full engineering investment. |
| 9 | Cheapest valid test for a DESIRABILITY (do-they-want-it) assumption? | Concierge MVP — manually deliver the actual experience to a small group of real customers to observe genuine behavior, not just stated interest. |
| 10 | Impact × Uncertainty prioritization matrix — how many quadrants and which to test first? | 4 quadrants. Test High Impact + High Uncertainty first — this is the riskiest/leap-of-faith assumption zone. |
| 11 | Common exam trap when identifying 'the riskiest assumption'? | Students often choose the easiest-to-test or most-obvious assumption rather than the one with the highest combined impact and uncertainty for business survival. |
| 12 | What should the Build-Measure-Learn loop minimize? | Total cycle time through the loop — the purpose is fast, cheap iteration toward validated learning, not maximizing build polish at any single stage. |
